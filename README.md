# Claudia

Личный dev-ассистент на Claude — доступ через браузер (PWA) с любого устройства, включая телефон. Не публичный продукт, только для личного использования.

## Локальный запуск (для проверки на Mac)

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
export ANTHROPIC_API_KEY=sk-ant-...
uvicorn main:app --reload
```

Открой http://localhost:8000

## Персистентность данных (важно!)

История чата, предложенные-но-не-подтверждённые изменения файлов и (если вводил через UI) зашифрованные API-ключи хранятся в `/app/data/` внутри контейнера — `claudia.db` (SQLite) и `master.key` (ключ шифрования). Простой рестарт процесса (например, из-за ошибки) это переживёт. **Но пересоздание контейнера (redeploy, обновление образа) сотрёт файлы**, если не подключить постоянный диск — и тогда ключи, введённые через интерфейс, придётся вводить заново (`master.key` пересоздастся новым, старые зашифрованные значения в базе станут нечитаемыми).

### На Railway
Settings сервиса → **Volumes** → Add Volume → указать путь `/app/data`. Railway сам сохранит содержимое между деплоями.

### На Hetzner (Docker)
Используй `-v claudia_data:/app/data` в команде `docker run` (пример ниже, в разделе про деплой на Hetzner) — именованный volume переживёт даже `docker rm` контейнера (но не `docker volume rm`).

## Деплой на Hetzner (рекомендуется — сервер физически не в России, обращение к Anthropic API идёт с "чистого" IP)

1. Создай VPS на Hetzner (самый дешёвый CX22 достаточно для старта)
2. Установи Docker на сервере:
   ```bash
   curl -fsSL https://get.docker.com | sh
   ```
3. Скопируй проект на сервер (git clone или scp)
4. Собери и запусти:
   ```bash
   docker build -t claudia .
   docker run -d -p 80:8000 \
     -e ANTHROPIC_API_KEY=sk-ant-... \
     -e GITHUB_TOKEN=ghp_... \
     -e GITHUB_REPO=owner/repo \
     -v claudia_data:/app/data \
     --restart unless-stopped \
     --name claudia \
     claudia
   ```
5. Открой `http://<IP-сервера>` в браузере телефона

### Рекомендуется: HTTPS через домен

PWA и "Добавить на экран" работают надёжнее с HTTPS. Проще всего — Caddy как реверс-прокси перед контейнером, он сам получает сертификат Let's Encrypt:

```bash
# на сервере, отдельным контейнером или через apt install caddy
caddy reverse-proxy --from claudia.твой-домен.ru --to localhost:8000
```

Для этого домен должен указывать на IP сервера (A-запись).

## Деплой на Railway (проще, но помни про гео-ограничения Anthropic — сервис Railway обычно тоже вне России, что и нужно)

1. Новый проект → Deploy from GitHub repo
2. В Variables добавить `ANTHROPIC_API_KEY`
3. Railway сам подхватит Dockerfile

## Выбор провайдера модели и API-ключи

Claudia может работать через два провайдера — переключение и ввод ключей прямо в интерфейсе (кнопка ⚙️ рядом с "Очистить"):

- **Anthropic напрямую**
- **OpenRouter** — полезно, если прямая оплата Anthropic недоступна (например, банк блокирует категорию мерчанта), а OpenRouter принимает твой способ оплаты, включая крипту

**Как задать ключ — два равноправных способа:**
1. Прямо в интерфейсе (⚙️ → вставить ключ в поле → Сохранить) — удобно, если правишь что-то с телефона и не хочешь лезть в панель Railway/Hetzner
2. Через переменные окружения сервера (`ANTHROPIC_API_KEY`, `OPENROUTER_API_KEY`) — классический способ

Если задано и то, и другое — **ключ, введённый в интерфейсе, имеет приоритет**.

**Как это защищено:** ключи, введённые через интерфейс, шифруются (Fernet/AES) перед сохранением в SQLite — мастер-ключ шифрования генерируется автоматически при первом запуске и хранится отдельным файлом (`master.key`) рядом с базой. Даже если файл базы данных (`claudia.db`) утечёт отдельно (например, случайный бэкап), сами API-ключи в нём не читаются как обычный текст.

Честно о пределах защиты: если у кого-то есть полный доступ к файловой системе твоего сервера — он получит доступ и к `master.key`, и к базе, и расшифрует ключи. Это не защита от взлома всего сервера, а защита от случайных утечек одного файла (лога, бэкапа базы без остального).

## GitHub-интеграция

Claudia может читать и изменять файлы в твоём репозитории напрямую через GitHub API.

1. Создай Personal Access Token: GitHub → Settings → Developer settings → Personal access tokens → Fine-grained tokens
   - Repository access: выбери конкретный репозиторий (например `devagent`)
   - Permissions: Contents → Read and write
2. Добавь две переменные окружения на сервере (Railway/Hetzner):
   ```
   GITHUB_TOKEN=ghp_...
   GITHUB_REPO=твой-юзернейм/devagent
   ```
3. Готово — теперь можно писать в чате что-то вроде:
   - "Покажи список файлов в репозитории"
   - "Прочитай agent.py"
   - "Почини опечатку в pwa_server.py"

Claudia сама решает, когда прочитать файл, а когда предложить изменение — в чате будет видно, какие именно вызовы она сделала (строки с 🔧).

**Изменения безопасны по умолчанию:** когда Claudia предлагает поправить файл, она не коммитит сразу — в чате появляется карточка с путём файла, сообщением коммита и превью нового содержимого, и две кнопки: **Применить** / **Отклонить**. Реальная запись в GitHub происходит только после того, как ты нажмёшь «Применить».

## Важно

- API-ключ никогда не хранится в коде — только в переменных окружения сервера
- История чата и предложенные изменения хранятся в SQLite — переживают рестарт процесса. Для того чтобы они пережили и redeploy/пересоздание контейнера, обязательно подключи persistent volume (см. раздел выше)
- Это личный инструмент, не для доступа посторонних пользователей — не давай ссылку на сервис никому
